## Установка зависимостей

```bash
pip install -r requirements.txt
```

Тестовые зависимости (уже включены в `requirements.txt`):
- `pytest` — фреймворк для запуска тестов
- `pytest-asyncio` — поддержка async-тестов
- `pytest-cov` — плагин для измерения покрытия
- `httpx` — async HTTP-клиент для тестирования FastAPI
- `aiosqlite` — async SQLite-драйвер для тестовой БД
- `locust` — инструмент нагрузочного тестирования

## Как запускать тесты

### Запуск всех тестов

```bash
python -m pytest tests/ -v
```

### Запуск с измерением покрытия

```bash
coverage run -m pytest tests/
coverage report -m          # Текстовый отчёт в консоль
coverage html               # HTML-отчёт → htmlcov/index.html
```

> **Важно:** используйте именно `coverage run -m pytest`, а не `pytest --cov`.
> Это необходимо для корректного отслеживания async-кода (SQLAlchemy + greenlet).

### Запуск отдельного файла или теста

```bash
# Все юнит-тесты
python -m pytest tests/test_unit.py -v

# Только тесты редиректа
python -m pytest tests/test_api_links.py::TestRedirect -v

# Один конкретный тест
python -m pytest tests/test_api_links.py::TestRedirect::test_redirect_success -v
```

### Нагрузочное тестирование (Locust)

Требуется **запущенный сервис** (например, через `docker-compose up`).

```bash
# С веб-интерфейсом (http://localhost:8089)
locust -f locustfile.py --host http://localhost:8000

# Без UI — 50 пользователей, 10 подключений/сек, 60 секунд
locust -f locustfile.py --host http://localhost:8000 \
       --headless -u 50 -r 10 --run-time 60s \
       --html report.html
```

## Описание тестовой инфраструктуры

### `tests/conftest.py` — фикстуры

Файл содержит общие фикстуры, которые автоматически подключаются ко всем тестам:

| Фикстура | Описание |
|---|---|
| `setup_database` | Создаёт все таблицы в SQLite перед каждым тестом и удаляет после. Каждый тест работает с чистой БД. |
| `setup_cache` | Заменяет Redis на `FakeCacheService` (in-memory словарь). Очищается перед каждым тестом. |
| `client` | Async HTTP-клиент (`httpx.AsyncClient`), отправляющий запросы к FastAPI-приложению через `ASGITransport`. |
| `auth_client` | То же, что `client`, но с зарегистрированным и авторизованным пользователем (`testuser`). |
| `test_cache` | Даёт доступ к `FakeCacheService` для ручной очистки кэша внутри теста. |
| `db_session` | Прямой доступ к тестовой БД для проверки/изменения данных в обход API. |

**Тестовая БД:** SQLite in-memory (`sqlite+aiosqlite://`) с `StaticPool` (единое соединение для всех сессий).

**Мок кэша:** `FakeCacheService` — наследник `CacheService`, хранит данные в обычном `dict`. Подменяется через `monkeypatch` во всех модулях, где используется `cache`.

### `pyproject.toml` — конфигурация

- `asyncio_mode = "auto"` — async-тесты запускаются автоматически без `@pytest.mark.asyncio`
- `pythonpath = ["."]` — позволяет импортировать `from src.xxx` из папки `tests/`
- `concurrency = ["greenlet", "thread"]` — необходимо для корректного отслеживания покрытия async-кода (SQLAlchemy async работает через greenlet)

## Описание тестов

### Юнит-тесты (`tests/test_unit.py`) — 31 тест

#### `TestGenerateShortCode` (4 теста)
Тестирует функцию генерации коротких кодов `_generate_short_code`:
- Длина по умолчанию соответствует настройке `settings.short_code_length`
- Произвольная длина кода
- Код содержит только буквы и цифры
- Генерация разных кодов (уникальность)

#### `TestCheckExpired` (3 теста)
Тестирует функцию проверки истечения срока `_check_expired`:
- Ссылка ещё не истекла → `False`
- Ссылка уже истекла → `True`
- Срок не задан (`expires_at=None`) → `False`

#### `TestPasswordHashing` (3 теста)
Тестирует хеширование паролей (`hash_password`, `verify_password`):
- Хеш корректно верифицируется
- Неверный пароль не проходит верификацию
- Хеш отличается от исходного пароля

#### `TestAccessToken` (2 теста)
Тестирует создание JWT-токенов (`create_access_token`):
- Токен создаётся с данными по умолчанию
- Токен создаётся с пользовательским временем истечения

#### `TestCacheService` (19 тестов)
Тестирует все методы `CacheService` с мок-объектом Redis:
- Подключение: успех и ошибка
- `get`, `set`, `delete`: без Redis (graceful degradation) и с Redis
- `get_json`, `set_json`: сериализация/десериализация JSON
- `get_int`, `set_int`: работа с целыми числами
- `disconnect`: с Redis и без
- Обработка исключений: `get`, `set`, `delete` при ошибках Redis не падают

### Тесты фоновой очистки (`tests/test_cleanup.py`) — 3 теста

Тестируют функцию `cleanup_task` из `src/main.py`, которая периодически удаляет истекшие и неиспользуемые ссылки.

Для тестирования `while True` цикла `asyncio.sleep` подменяется моком, который пропускает первый вызов (давая выполниться логике очистки) и на втором выбрасывает `CancelledError`, завершая цикл.

- **Очистка истёкших ссылок:** ссылка с `expires_at` в прошлом удаляется, запись переносится в `link_history` с `reason="expired"`
- **Очистка неиспользуемых ссылок:** ссылка с `last_used_at` старше порога (90 дней) удаляется, запись переносится в `link_history` с `reason="unused"`
- **Нет ссылок для очистки:** задача завершается без ошибок

### Нагрузочное тестирование (`locustfile.py`)

Сценарий для **Locust**, симулирующий реальную нагрузку на API.

Каждый виртуальный пользователь:
1. Регистрируется и логинится при старте
2. Выполняет задачи с разными весами:

| Задача | Вес | Описание |
|---|:---:|---|
| `create_link` | 3 | Создание новой короткой ссылки |
| `redirect_link` | 5 | Переход по короткой ссылке |
| `get_stats` | 2 | Получение статистики по ссылке |
| `search_link` | 1 | Поиск по оригинальному URL |

Вес определяет относительную частоту вызова задачи. Редирект выполняется чаще всего (вес 5), что отражает реальный паттерн использования.
